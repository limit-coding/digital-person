# 数字镜像架构草案

## 原则

- 原始材料只读，所有派生记录都能追溯到源文件哈希。
- 你的原话、他人原话、AI 生成内容必须保持不同 provenance（来源身份）。
- 稳定价值、短期状态和历史版本分开表示。
- “像你说话”与“预测你行动”分别训练、分别评测。
- 每个行为预测都返回候选行动、概率、证据和不确定性。

## 分层系统

### 0. 镜像租户边界

系统把每个建模对象视为独立镜像租户：

- `personal`：私人本人镜像，只从本地私有事件目录加载，所有事件和预测接口都要求登录；
- 历史人物目录、时期材料与 `POST /api/ask` 属于公开研究界面；无需私人会话，但模型调用受服务端限流。
- `historical/<figure_id>`：历史人物镜像，只从该人物自己的公开资料目录加载；
- 禁止跨人物检索，禁止历史人物语料进入本人风格或判断训练，禁止私人材料进入公开人物接口；
- 公共目录接口只返回人物摘要，单个人物详情通过明确的 `figure_id` 加载，目录名必须与人物 ID 一致。

前端可以在同一站点展示两种产品面，但后端数据根、API 命名空间、缓存策略和访问控制保持分离。

### A. 数据与来源层

每个最小记录应包含：

- `record_id`：稳定标识；
- `source_sha256` 与源路径；
- `author_role`：`self`、`other`、`ai`、`unknown`；
- `occurred_at` 与 `written_at`；
- `source_kind`：传记、规则、聊天、文章、外部评价等；
- `sensitivity` 与允许用途；
- `confidence`：对作者、时间和事实可靠性的置信度。

回忆性传记必须区分事件发生时间与写作时间。AI 点评不能成为表达风格训练样本。

### B. 记忆层

- 情景记忆：事件、参与者、背景、行动与结果。
- 语义记忆：长期信念、偏好、能力、反复出现的判断。
- 规则记忆：机器模式中的硬规则、例外条件和版本有效期。
- 关系记忆：去标识化人物节点、关系类型、互动与变化。
- 状态记忆：睡眠、压力、资源、关系阶段、人格系统版本。

检索排序综合当前问题、人物关系、时间接近度、人格版本和证据可靠性，不能只依赖语义相似度。

### C. 模型层

第一阶段使用强基础模型和检索增强，得到不改模型参数的基线。之后按增益逐层引入：

1. 风格适配器：仅使用确认属于你的文本做 SFT/LoRA。
2. 判断适配器：使用场景、真实判断和理由训练。
3. 偏好优化：根据你对候选答案的选择构造 chosen/rejected 对。
4. 行为转化器：先预测判断，再预测 `执行判断 / 转向替代项 / 继续等待`；把行动成本、准备动作、他人依赖、时间压力、情绪激活和相似事件执行率作为监督信号。
5. 行为预测器：将判断分布与转化状态组合成最终行动概率，并单独做校准。

不从零预训练 Transformer；当前个人语料适合适配与记忆，不足以重新学习通用语言能力。

### D. 两种镜像

- `actual_self` 以历史实际行为和未来密封预测为金标准。
- `constitutional_self` 以机器模式规则和用户确认的修订为金标准。

同一场景可以同时运行两种镜像，差异本身就是有价值的信号：它表示现实行为与制度化理想之间的距离。

### E. 历史回放器

历史回放不是让模型知道结局后解释过去，而是在事件发生前设置时间截面 `cutoff_at`。系统只能检索当时已经产生、当时的你能够知道的证据，然后重建：

- 当时认真考虑过哪些选项；
- 哪些价值、欲望、风险或关系目标相互冲突；
- 哪些信息不确定；
- 对各选项的主观权重与纠结程度；
- 最可能作出的判断和最可能执行的行动。

`当时判断`、`实际行动`、`事后结果`、`后来复盘` 和 `AI 点评` 是五类不同标签。AI 点评可用于发现候选解释、比较视角或辅助人工标注，但默认既不作为你的原话，也不作为历史回放输入。

我们不把模型自由生成的长推理文本当作可信的“内心活动”。可评测对象是结构化的审议状态：候选选项、冲突轴、未知信息、概率和证据。你的同期聊天或笔记中明确写出的想法，才是还原内心状态的主要金标准。

### F. 历史人物数字切片

历史人物模式沿用回放器的时间隔离，但增加史料批判字段和展示约束：

- 公开表态、私人通信、会议文件、实际行动、他人回忆与研究解释分层；
- 每条材料标记日期、材料类型、与人物认知的接近程度、来源链接和置信度；
- 同时展示多个竞争性行动假设及其证据编号，概率总和必须为 1；
- 截止点之后的材料可以作为结果标签或反证，但必须明确标记为不得进入盲测；
- 第一人称模拟只能作为解释性界面，不能作为史实或心理真值输出。

### G. 时期化开放提问与模型路由

- 人物可以拥有任意数量的 `periods`；时期包含时间范围、语境、可支持锚点、当时未知和证据入口。
- 开放问题必须同时指定 `figure_id` 与 `period_id`，模型输入只装配该人物、该时期和本轮有限对话历史。
- `grounded` 模式偏向保守重建，`counterfactual` 模式允许天马行空的推演，但两者都必须分开显示史料支持、推测和未知。
- 服务端不信任模型自行标记的“史料支持”：只有时期档案里的锚点能进入支持层，额外断言自动降级为创造性推演，证据编号也必须在时期白名单内。
- 模型路由支持内置证据骨架、Google Gemini、DeepSeek、OpenAI、OpenAI 兼容接口和 Ollama。提供商凭据只从环境变量读取，远程提问接口要求会话登录并按客户端限流。
- 前端可以把同一问题并行发送给多个已选模型；每个模型独立给出 `judgement`，界面并排保留分歧，不设置一个“裁判模型”覆盖其他结果。

### H. 私人总体画像

- 私人画像只聚合结构化事件标签，不把原文、源路径或源哈希暴露给浏览器。
- 单事件回放只向模型发送截止点前的脱敏编译结果；标签、真实行动、结果与事后材料留在服务端。
- DeepSeek、Gemini 等模型独立预测判断与行动，前端用结构化字段直接计算一致/分歧，不指定某个模型总结其他模型。
- 每次向云模型发送私人聚合画像或事件截面前都要求显式授权。
- 所有跨事件模式必须同时显示样本数与置信度；低样本结论称为工作假设，不称为稳定人格。
- 判断与行动分开统计，临场改道作为信号保留；缺少结果回访不会被当作执行失败。
- `POST /api/me/ask` 只装配聚合指标与有限对话历史。内置/本地模型无需云端授权；任何远程模型都必须显式设置 `allow_cloud=true`。
- 服务端再次对白名单做约束：只有已有结构化信号可以进入“记录支持”，模型自行补充的情境自动进入“模型推演”。

事件挖掘也采用两层隔离：候选审稿器可以看前后文，只判断证据是否足够；正式预测器只能看截止时间以前的输入。审稿模型的结论只是排序信号，必须经过源消息编号、时间、角色和语义一致性复核后才能成为机器草稿，更不能直接成为本人真值。

## 建议的迭代顺序

1. 数据审计与用途授权。
2. 统一记录、去标识化和时间轴。
3. 无训练 RAG 基线。
4. 建立冻结的历史回放集和 30 天前瞻评测。
5. 风格 LoRA/SFT。
6. 决策偏好优化和概率校准。
7. 消融实验：逐项证明记忆、时间状态和微调分别带来多少增益。

## 尚待用户确认

- 敏感原文能否发送给云模型；默认不能。
- `actual_self` 与 `constitutional_self` 的第一版优先级；默认并行保留。
- 哪些第三方聊天取得了可用于本地建模的授权；默认仅本地、去标识化。
- 第一版服务形态（命令行、Web、微信式界面）；这不影响当前数据层工作。
