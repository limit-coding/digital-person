# Mirror Atlas 开发日志

## 2026-07-20 · 历史人物镜像第一阶段

### 产品决策

- 将产品拆成公开的“历史人物数字切片”和受登录保护的“个人镜像”两层。
- 历史人物不是角色扮演：输出竞争假设、概率、同期已知、同期未知和来源入口，不宣称还原不可验证的真实内心。
- 每位人物采用独立目录、独立 ID 和独立加载边界；人物之间以及历史人物与本人之间禁止检索和语料混用。

### 工程节点

- 新增隔离的历史人物目录加载器及公开只读 API。
- 保留私人事件 API 的登录、会话签名、限流、无缓存和云端脱敏门。
- 重做响应式前端：人物档案索引、时间截面、竞争假设、知识边界、证据卡片和私人镜像入口。
- 新增社交分享封面，视觉上不让任何单一人物代表整个项目。
- 新增人物目录一致性、假设概率、证据引用和公私 API 边界测试。

## 2026-07-20 · 同题多镜与私人提问

- 历史人物提问从单模型选择升级为最多 4 个模型并行回答；新增 `judgement` 核心判断，并排保留模型间分歧。
- 私人总体画像新增直接提问台。云模型只接收聚合指标与有限对话历史，必须由用户勾选授权；聊天原文、源路径和身份信息不会装配进请求。
- 毛泽东档案从 1 个时期、1 张切片扩展为 3 个时期、3 张切片：1949年和平条件、1956年《论十大关系》、1966年“五一六通知”。
- 切片标签与时期提问联动，避免展示某一决策节点却用另一个时期回答。
- 本地双模型实测：DeepSeek 对私人改道条件给出更积极的情境推断；Gemini 因只有 1 次改道样本而拒绝形成强模式。两者额外断言均被限制在“模型推演”层。
- 自动化测试增至 64 项；人物 JSON、概率和证据引用检查、Python 编译与前端语法检查通过。

## 2026-07-20 · 私人事件多模型回放

- 修正第 06 号“长文是否发送”等事件仍显示单一“模型判断”的缺口：`POST /api/predict` 现在接受明确的 `model_id`，不再写死 DeepSeek。
- 事件页新增模型多选与云端授权；只发送截止点前的脱敏编译切片，事件标签、真实行动、结果、聊天原文和源路径不进入模型请求。
- 回放完成后先显示结构化结论矩阵，分别比较“当时会如何判断”与“最终会如何行动”，并明确标记一致或分歧；详细概率随后展示。
- 第 06 号切片真实双模型验收：DeepSeek 与 Gemini 都判断会发送；DeepSeek 预测最终暂不发送（50%），Gemini 预测最终发送（65%），页面标记为“判断一致 / 行动有分歧”。真实行动为发送。
- 自动化测试增至 66 项；Python 编译、前端语法、格式检查与浏览器端双模型调用均通过。

## 2026-07-20 · `mirror.learnpath.tech` 上线

- 将应用部署到共享服务器的 `/opt/digital-person`，由独立 `digital-mirror` 系统用户运行；FastAPI 只监听 `127.0.0.1:8010`，不占用公网应用端口。
- Nginx 为 `mirror.learnpath.tech` 增加独立虚拟主机，没有删除或覆盖服务器上的其他站点。
- 通过 Certbot 签发独立 ECDSA 证书，HTTP 自动跳转 HTTPS，证书已纳入自动续期。
- 公网验收：主页、健康接口与人物接口正常；13 位人物、6 条结构化私人切片加载成功；未登录访问私人 API 返回 401。
- 生产环境启用 DeepSeek 与 Gemini。Gemini 直连最初被 Google 以出口地区不支持拒绝；现使用独立、仅监听 `127.0.0.1:18181` 的提供商专用出口，DeepSeek 继续直连。
- Gemini 代理只通过 `DIGITAL_MIRROR_GEMINI_HTTPS_PROXY` 应用于 Google 请求，不改变其他模型的网络路径；代理配置和凭据只保存在服务器受限文件中，不进入 Git。
- 修正一项干净环境测试缺陷：事件回放测试改用仓库内合成模板，不再依赖本机未提交的私人事件文件；本地与服务器均可独立运行 67 项测试。
- 生产同题验收：牛顿“剑桥形成期”问题分别通过 Gemini 与 DeepSeek 返回 200，并保留两套独立判断。
